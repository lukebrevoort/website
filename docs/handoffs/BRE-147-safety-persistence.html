The public canvas now has guardrails that feel like part of it.

Authored notes stay playful and instant. Live inference is deliberately scarce, verified, pseudonymous, and fail-closed. The visitor's board remains local and survives refreshes—even when every server-side control says “stop.”

What works without a model

Six authored starting points

Each suggestion returns a cached semantic canvas patch. It uses no provider token, ignores live quotas, and remains available during outages.

Local recovery

The active board is debounced into browser storage, bounded to 3.5 MB, and restored on refresh. No canvas content is sent anywhere until a visitor submits.

Clear new-board control

The top-right control confirms before clearing a non-empty board, removes the local recovery copy, resets conversation context, and starts fresh.

Fail-closed live mode

Missing Redis, HMAC, Turnstile, or provider configuration stops inference in production and points visitors back to authored notes. Existing marks remain untouched.

Production setup

Add distributed counters

Create Vercel KV or Upstash Redis and set KV_REST_API_URL plus KV_REST_API_TOKEN. The route refuses live inference in production if they are absent or unreachable.

Add a separate HMAC secret

Generate at least 32 random bytes for CANVAS_USAGE_HMAC_SECRET. This rotates session/IP digests daily and is not the provider credential.

openssl rand -base64 32

Configure Turnstile

Set NEXT_PUBLIC_TURNSTILE_SITE_KEY, TURNSTILE_SECRET_KEY, and TURNSTILE_EXPECTED_HOSTNAME. Only the site key may be public.

Set the project cap below free quota

Use an unbilled provider project during validation. Set CANVAS_PROJECT_DAILY_LIMIT below its active daily quota. There is no automatic provider or billable fallback.

Create the upstream Firewall rule

In Vercel → Firewall → Custom Rules, rate-limit POST /api/canvas-agent to 10 requests per IP per 60 seconds. This absorbs bursts before the function and complements—rather than replaces—the application limits.

Bound log retention

Set the Vercel log drain or project retention to the shortest operational window (recommended: 7 days). The application emits request ID, event, duration, provider, and operation count only.

Deployment order matters: add Redis, HMAC, Turnstile, provider budget, and Firewall settings before enabling unrestricted public traffic. Until then, authored starters remain functional while custom live requests fail safely.

Fast manual verification

  1. Run npm test and npm run build.
  2. Open /explore on desktop.
  3. Choose an authored starter; verify editable native marks appear.
  4. Refresh; verify those marks recover.
  5. Add a visitor mark, refresh again, and verify it recovers.
  6. Use “new board,” cancel once, then confirm; verify the canvas clears.
  7. Submit a custom prompt without live config; verify the board remains unchanged.
  8. With Turnstile configured, verify a custom prompt requires the human check.
  9. Send two live requests rapidly; verify cooldown or in-flight rejection.
  10. Lower the session limit to 1; verify the next request falls back gracefully.
  11. Disable Redis in production mode; verify live mode fails closed.
  12. Repeat starter, refresh, and reset on a mobile viewport.
  13. Inspect browser console for runtime errors.
  14. Inspect logs and confirm no prompt, image, raw IP, or secret appears.
