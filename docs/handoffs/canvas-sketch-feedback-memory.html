Explore canvas · format memory v1 · Jul 2026

Remember good layouts as priors, not facts.

After a live sketch is applied (including Apply anyway), visitors can thumbs-up / thumbs-down the layout. Upvoted compact recipes are stored by prompt fingerprint and later injected as approvedFormats — layout guidance only. Knowledge packs remain the factual source. No blind board replay.

What shipped

Compact 👍 / 👎 UI

Sketchbook chip on /explore after a live apply. Authored starters skip feedback.

Feedback API

POST /api/canvas-agent/feedback accepts prompt, summary, vote, optional note, recipe or patch. Rate-limited per session/IP digest.

Redis rollup + local fallback

Keyed by fingerprint; capped list; ranked by net score + recency. Memory store outside production when Redis is absent.

Director priors

Live generate retrieves top 1–2 approved formats and injects them with an explicit “priors only” prompt rule.

Fingerprint

Built from knowledge-matched project ids (same alias/keyword scoring as packs) plus one primary intent bucket (compare, how, architecture, …). Near-paraphrases like “Compare MALCOM and Dispatch” and “How do Dispatch and MALCOM differ?” share a key.

v1 product choices

QuestionDecision
DownvotesDecrement score; entries with netScore ≤ 0 are excluded from retrieval (kept in rollup until pruned).
RetentionRedis TTL ~90 days; list capped at 12 per fingerprint.
What’s storedCompact recipe (shape mix, coarse grid, themes, truncated roles) — not a full board snapshot.
Out of scopeBlind replay, auto-promote to authored starters, Turnstile / usage-lease / safety hard-fail changes.
If product wants hard-delete on downvote, shorter retention, or opt-out of cross-visitor sharing, say so on the PR — v1 prefers a tight demotion model.
